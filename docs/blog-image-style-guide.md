# ClawLite Blog Image Style Guide

_Last updated: 2026-03-23_

## Purpose

This guide defines the visual standard for all ClawLite blog images.

The goal is simple:
- make blog posts feel consistent
- make product value obvious at a glance
- avoid weak screenshots, washed-out video frames, and generic AI-looking filler art
- support ClawLite's positioning: **one-click install, cheaper tokens, lower friction, boring reliability**

## Brand fit

Every blog image should reinforce at least one of these ClawLite ideas:
- **one-click install**
- **faster path to first value**
- **cheaper token economics / BYOK**
- **less setup friction**
- **reliable, understandable workflow**

If an image looks impressive but does not help explain one of those, do not use it.

---

## Core rules

### 1. Prefer product truth over decoration
Use real UI, real steps, real product surfaces.

Preferred image types:
1. actual product screenshots
2. annotated screenshots
3. clean comparison graphics
4. simple branded diagrams

Avoid using decorative images just to “fill the post.”

### 2. Never use random video frames as article images
Do **not** use images extracted blindly from videos or GIFs.

Reason:
- they often catch blank transitions
- they look washed out or low-signal
- they reduce trust
- they make the post look unfinished

If a video is the source material, manually choose or recreate a static screenshot.

### 3. One image = one message
Each image should communicate exactly one thing:
- install entry point
- first successful run
- pricing comparison
- setup checklist
- workflow overview
- before/after comparison

If the viewer cannot tell what the image is proving within 2 seconds, it is too weak.

### 4. Make the useful area dominant
The main information must occupy most of the frame.

Bad:
- tiny UI in the middle of a huge empty background
- browser chrome dominating the screenshot
- large white areas with one small dialog
- transitional loading states

Good:
- the core product action is large and readable
- the screenshot is cropped to the meaningful region
- visual noise is removed

### 5. Consistency beats novelty
Blog images should feel like one system, not a new style every article.

## Image system

## A. Hero image standard

Use for:
- article top image
- social preview source candidates
- key tutorial / comparison posts

### Hero image goals
A hero image should instantly answer:
- what is this post about?
- what product action or benefit is being shown?

### Hero image content patterns
Use one of these patterns:

#### Pattern H1 — Product proof hero
- one strong product screenshot
- optional short label chip
- focus on setup, install, pricing, dashboard, or success state

Best for:
- tutorials
- install guides
- feature explainers

#### Pattern H2 — Comparison hero
- two-column or split layout
- ClawLite on one side, alternative on the other
- clear contrast in complexity / cost / speed

Best for:
- vs articles
- pricing comparison
- positioning pages

#### Pattern H3 — Workflow hero
- 2–4 connected steps
- arrows or cards
- simple journey from install → first task → useful result

Best for:
- onboarding content
- operational explainers

### Hero image visual rules
- aspect ratio: **16:9** preferred
- safe fallback: **1.91:1** for social-sharing compatibility
- background: light neutral or ClawLite brand-safe gradient
- keep layout clean and sparse
- show no more than 1 main claim
- use a real product screenshot whenever possible
- no more than 12 words of text inside the image

### Hero image text rules
Allowed text examples:
- One-click OpenClaw install
- First useful run in minutes
- Cheaper tokens, less setup friction
- OpenClaw vs ClawLite

Avoid long headline text inside the image.
The article title already exists outside the image.

---

## B. Body image standard

Use for in-article support images.

### Body image roles
Each body image should do one of these jobs:
- show a step
- prove a claim
- reduce ambiguity
- summarize a choice
- visually break up a dense section with useful information

### Body image types

#### B1 — Step screenshot
Use when explaining a tutorial step.

Requirements:
- crop tightly around the relevant UI
- show the exact button, panel, or result being discussed
- caption should state what the reader is seeing

Example caption:
- ClawLite install entry and setup path
- First successful OpenClaw run inside ClawLite

#### B2 — Annotated screenshot
Use when raw UI is not clear enough.

Allowed annotations:
- arrows
- highlight box
- numbered markers
- one short note

Keep annotations minimal. Avoid turning screenshots into clutter.

#### B3 — Comparison table graphic
Use when explaining differences in:
- cost
- setup time
- control level
- technical difficulty

Should be readable on mobile.

#### B4 — Checklist or framework card
Use when the post contains a process, checklist, or decision tree.

Best for:
- beginner guides
- setup readiness
- “how to choose” posts

## Composition rules

### Cropping
Always crop to the meaningful content.

Checklist:
- remove large empty margins
- remove obvious dead space
- reduce distracting browser chrome unless it adds context
- keep the key interface readable on mobile

### Readability
If the main UI text is too small to read, either:
- crop tighter
- zoom the relevant area
- split into multiple images
- annotate the important section

### Brightness / contrast
Reject images that are:
- washed out
- transitional white frames
- mostly blank backgrounds
- low-contrast screens with unreadable UI

### Density
Reject images if:
- more than 40% of the frame feels visually useless
- the key action is not obvious
- the screenshot feels like a raw screen capture rather than an editorial asset

---

## Forbidden image patterns

Do not publish these:

### F1 — Blank-frame video grabs
Examples:
- loading state
- fade transition
- paused animation mid-flash
- white overlay moment

### F2 — Generic AI illustration slop
Examples:
- random robots
- glowing brains
- sci-fi dashboards unrelated to product truth
- lobster mascots used as filler instead of proof

The mascot can appear occasionally, but never as a substitute for product proof.

### F3 — Tiny-UI screenshots
If the useful UI occupies a small fraction of the image, do not use it.

### F4 — Screenshot soup
Avoid multi-window clutter, too many floating panels, unreadable tabs, or chaotic desktop captures.

### F5 — Mismatch images
Do not use an image that shows one thing while the paragraph discusses another.

## Visual language

### Tone
ClawLite blog images should feel:
- practical
- clean
- trustworthy
- lower-friction
- not overdesigned
- not hypey

### Color behavior
Prefer:
- white / off-white / soft gray base
- blue accents where useful
- restrained contrast
- occasional brand imagery only when helpful

Avoid:
- neon cyberpunk styling
- too many gradients
- dark noisy backgrounds unless the product UI genuinely needs it

### Border / frame treatment
Recommended:
- subtle border
- light shadow
- rounded corners
- enough padding if placed on colored backgrounds

This matches the existing site style well.

---

## File naming rules

Use descriptive file names based on function, not vague labels.

Good:
- `install-entry.jpg`
- `first-successful-run.jpg`
- `pricing-comparison.jpg`
- `setup-checklist.jpg`
- `dashboard-overview.jpg`

Bad:
- `image1.jpg`
- `screenshot-final-final.jpg`
- `frame-22.jpg`
- `clip-export.jpg`

Format:
- lowercase
- hyphen-separated
- no dates unless versioning matters

## Recommended production workflow

## Workflow W1 — Tutorial article
1. identify the 2–4 moments that actually matter
2. capture real screenshots for those moments
3. crop each screenshot to the useful area
4. add a caption that states the proof
5. reject any frame that looks transitional, blank, or washed out

## Workflow W2 — Comparison article
1. define the one comparison that matters most
2. create one hero comparison visual
3. use one supporting table/graphic only if needed
4. keep copy short and legible

## Workflow W3 — Concept / thought-leadership article
Prefer one of these:
- simple comparison chart
- workflow diagram
- proof-point card
- minimal branded framework visual

Do not force a product screenshot if the post does not naturally need one.
But also do not use meaningless filler art.

## Pre-publish QA checklist

Before any blog image goes live, check:

### Signal quality
- [ ] the image proves a real point
- [ ] the key message is obvious within 2 seconds
- [ ] it supports ClawLite positioning

### Visual quality
- [ ] not blank or washed out
- [ ] no random video-frame artifacts
- [ ] readable on mobile
- [ ] cropped to the useful area
- [ ] no unnecessary clutter

### Brand quality
- [ ] practical, trustworthy tone
- [ ] not generic AI slop
- [ ] not hype-first
- [ ] fits the rest of the blog system

### Publishing quality
- [ ] file name is descriptive
- [ ] alt text states what the reader sees
- [ ] caption explains why it matters
- [ ] image path matches article slug structure

## Reusable templates

## Template T1 — Screenshot caption
`[What the reader is seeing] + [why it matters]`

Examples:
- ClawLite install entry and setup path
- First successful OpenClaw run after setup
- Pricing comparison showing BYOK vs hosted token usage

## Template T2 — Alt text
`Short factual description of the interface or comparison`

Examples:
- ClawLite installer showing the OpenClaw setup entry point
- OpenClaw first-run success screen inside ClawLite
- Comparison table of ClawLite vs ChatGPT Plus pricing

## Template T3 — Image brief for a human designer or model
Use this when creating a new blog visual:

```text
Create a clean blog image for ClawLite.
Goal: show [single message].
Audience: developers / operators / founders evaluating AI assistant setup.
Visual style: practical, trustworthy, minimal, product-led, light background, subtle border/shadow.
Must include: [real screenshot / comparison card / checklist / workflow steps].
Must avoid: generic AI art, cyberpunk effects, clutter, long text, blank space, random video-frame look.
Format: 16:9.
Text inside image: max 8-12 words.
Brand angle: one-click install / cheaper tokens / lower setup friction / boring reliability.
```

## Template T4 — Screenshot selection rule
When multiple candidate screenshots exist, choose the one with:
1. the clearest useful action
2. the least empty space
3. the highest contrast and readability
4. the strongest proof of the paragraph claim

---

## Default image plan by article type

### Install / tutorial post
- 1 hero image
- 2 body screenshots
- optional 1 checklist card

### Comparison post
- 1 comparison hero
- 1 supporting comparison visual or table

### Pricing / token economics post
- 1 cost comparison visual
- optional 1 workflow-cost explanation card

### Thought piece / positioning post
- 1 framework visual or proof card
- optional 1 product screenshot if it materially supports the claim

---

## Decision rule

If forced to choose between:
- a flashy image
- a plain but truthful image

Choose the plain but truthful image.

For ClawLite, **credibility beats spectacle**.
